# 0.1.24 hardening — 2026-10-20

No live test. The user could not log out or change settings, and installing a
new ad-hoc build would have required granting window-control permission again.
Everything below is from crash reports, on-disk state and `scripts/test.sh`.

## Evidence on the development Mac

- `~/Library/Logs/DiagnosticReports/Kolom-2026-10-19-163058.ips` and
  `Kolom-2026-10-20-121609.ips`: 0.1.23 `EXC_BREAKPOINT` in
  `Dictionary.init(uniqueKeysWithValues:)` called from
  `KolomController.refresh(force:)` (Controller.swift:344 before formatting).
  Discovery produced the same window ID for two windows.
- After the 12:16 crash the watchdog restored windows: `last-recovery.json`
  reports 10 scanned, 10 checked, 10 verified, 0 remaining.
- The watchdog did not restore the wallpaper. `wallpaper-restore.json` had
  7 records; 6 recorded Kolom's own `theme-dark.png` as the original, keyed by
  CGDirectDisplayID numbers that no longer matched any screen. The connected
  display was left showing `theme-dark.png`.

## What 0.1.24 changes

See `CHANGELOG.md`. Checks added: unique window identities (including
2,000 randomized cases), bottom-edge parking for a display with neighbours on
both sides, safe agent-file reads (FIFO, symlink, device, oversize), operation
bounds and scoped grid undo.
